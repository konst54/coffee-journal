# Соразмерный SDLC

## Изменение
1. Прочитать AGENTS/HANDOFF и текущую удалённую ветку. Назначить одного владельца; другие работают в отдельных ветках/непересекающихся файлах.
2. Зафиксировать цель, критерии приёмки, риски и затронутые данные/интерфейсы в issue или BACKLOG.
3. Маленькая вертикальная задача: тест → наблюдаемый RED → минимальная реализация → GREEN → рефакторинг. Команды и наблюдавшийся результат оставить в PR/хэндоффе.
4. Общие gates: backend unittest, frontend Node tests, PostgreSQL security tests, dependency audit, diff check. Для UI дополнительно настоящий браузер 390px/1280px. Для cloud — проверка реального auth/API; эмуляция не заменяет staging.
5. Проверить безопасность: секреты/личные данные в Git, источники в экспорте, XSS, анонимный и чужой доступ, повторы, атомарность, миграции, backup/restore.
6. Коммит/пуш рабочего checkpoint, проверить удалённый SHA. PR с целью, проверками, рисками и ограничениями; не сливать незавершённый код в main.

## Передача и лимиты
HANDOFF содержит STATUS, владельца, implementation SHA, команды, результаты, блокеры и следующий шаг. Пока IN_PROGRESS — следующий агент ждёт. READY_FOR_HANDOFF публикуется последним коммитом; автор больше не изменяет переданную ветку. Resume после обновления квоты не отменяет владельца Claude.

Квоту проверять в начале и на крупных рубежах; чаще при низком остатке. Сохранять checkpoints до исчерпания. Обычный обрыв не требует нового согласования уже разрешённой работы: прочитать текущее состояние и продолжить, не повторять слепо записи. Пользователь разрешил emergency fallback только на финальный коммит/пуш и хэндофф, не объёмную разработку.

## CI и релиз
На момент этапа доступ GitHub имеет repo, read:org, gist без workflow. Поэтому CI проверен локально, remote Actions не заявляется. Шаблон `docs/ci-template.yml` следующий агент может перенести в `.github/workflows/ci.yml` после разрешения workflow scope. Защиту main и staging/cloud rollout настроить отдельно; не обходить разрешения.

Продакшен-релиз требует зелёных проверок, staging auth/RLS/API, подтверждённой публикации сайта, плана отката и восстановления приватной базы. `READY_FOR_HANDOFF` не значит `PRODUCTION_READY`.
