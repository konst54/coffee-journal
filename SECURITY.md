# Security review — initial checkpoint

## Модель угроз
Личные вкусовые заметки, история проб и фотографии не должны утечь в Git, Pages, анонимный API или другой аккаунт. OCR/названия/комментарии считаются недоверенными данными. Приватный репозиторий не заменяет изоляцию данных. Агент с host filesystem access доверенный; процессы с тем же uid не являются изолированными арендаторами.

## Реализовано и проверено
- Python: allowlist сущностей/полей, параметризованные SQL-значения, проверка UUID/чисел/дат, отказ NaN/Infinity/bool-рейтингу; ссылки и тип оборудования проверяются до записи. Нет SQL-идентификаторов из произвольного ввода.
- Idempotency + BEGIN IMMEDIATE: повтор возвращает существующий ID, конфликт payload отвергается, ошибка откатывается. Связи проверяются приложением; реальных SQL FK между JSON-сущностями нет. Обычные произвольные прямые SQLite writes обходят эти проверки и не являются supported API.
- DB/backup/export файлы 600, создаваемые private директории 700; отказываем symlink paths; export/backup не перезаписывают существующие файлы. Не заявляем защиту от конкурентного захвата файловой системы процессом того же uid. Без шифрования at rest.
- Source fields исключаются из экспортируемых записей, вложенный sensory ограничен известными числовыми осями. Остальные заметки всё равно приватны.
- UI: динамические строки через textContent, CSP без inline script/unsafe-inline и внешних CDN. Реальный браузер проверяет работу, отсутствие ошибок/форм и overflow 390/1280px. Node-test проверяет буквальный рендер XSS-подобной строки.
- Supabase projection: SELECT только authenticated+owner RLS; anon не имеет прав; direct writes authenticated запрещены; RPC SECURITY DEFINER с пустым search_path, writer allowlist, auth.uid, блокировкой и expected revision. Не возвращает данные другого владельца. Приватные source поля рекурсивно запрещены. Никаких service-role keys в браузере.
- PGlite выполняет реальные PostgreSQL SQL/RLS проверки (auth.uid эмулирован); npm audit SQL tooling: 0 уязвимостей в наблюдаемом запуске.

## До продакшена — обязательно
- Облачный Supabase не создан/не подключён. Перепроверить auth, RLS и grants через реальные HTTP API и двух пользователей. PGlite не проверяет GoTrue, PostgREST, JWT или настройки проекта.
- Cloud adapter, auth lifecycle, refresh/logout, локальный writer и revision conflict ещё не связаны; snapshot не валидирует всю предметную модель по каждой записи, только оболочку/размер/приватные ключи. Публиковать только validated CLI export через доверенного writer.
- Update с историей версий и тест восстановления из backup есть; удаления/архивирования нет. История содержит приватные source-поля и не экспортируется.
- Ограничить регистрацию, задать точные redirect URLs, writer allowlist и реальные настройки CORS. Проверить заголовки на хостинге; meta-CSP не может установить frame-ancestors, HSTS или HTTP cache headers.
- Auth-токены только в памяти браузера/защищённом серверном хранилище; не в URL query, Git, localStorage или сообщениях. Не ставить service_role в frontend. Не логировать токены.
- Фото содержат потенциальные EXIF/PII: хранить приватно; при будущей выдаче вне доверенного storage нужна санитизация/контроль доступа.
- CLI отвергает входные файлы больше 5 МиБ до разбора JSON и пакеты больше 200 записей; глубокая вложенность даёт чистую ошибку. Будущий сетевой endpoint всё равно обязан ставить свои лимиты размера/частоты.

Документ — ограниченный обзор и фактические проверки, не обещание полной защищённости.
